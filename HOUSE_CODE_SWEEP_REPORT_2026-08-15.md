# HOUSE Code Sweep — Report (2026-08-15/16)

A deep, adversarially-verified code sweep across all six HOUSE repos, hunting redundancies, kludges, footguns, and cleaner-structure opportunities. **Analysis only — no app code was touched.** Full per-finding detail (evidence quotes, line numbers, direction sketches) lives in `HOUSE_CODE_SWEEP_2026-08-15/findings/*.md`; this report is the ranked synthesis. Working materials (briefs, known-register, triage + refute verdicts, state) are in the same directory.

**Method in one paragraph.** Eleven sweep agents covered the six repos (EXPO ×3 slices, MISE ×2, DOOR, HUB, PROOF+portal, plus three cross-app slices: contract conformance, publish paths, shared-origin storage/vocabulary), each running a fixed protocol — grep battery, risk-targeted attentive reads, load-bearing-write traces, doc-drift checks — against pinned HEADs (door `7500521` · expo `2686de6` · hub `9ecce4c` · recipe-hub `6ea8b30` · proof `b3dc772` · house `a01a02a`). Findings were deduped against a compiled register of already-known/ruled items, then **every P1 and every fork-marked finding (35 findings) went through an adversarial refute pass by fresh agents instructed to disprove them: 35/35 CONFIRMED, zero refuted**, several strengthened, and a 6-item random calibration sample of P2/P3s also came back 6/6 — so the unrefuted tail's confidence labels held calibration. Ruled decisions (single-file architecture, retired modularization proposals, deferred lines) were treated as constraints, not re-litigated.

**Headline counts:** 93 raw findings → **87 unique** after cross-slice merges: **29 P1 · 39 P2 · 19 P3 · 0 P0**. Status split: ~78 NEW, ~9 KNOWN-with-new-evidence. Five defects were found independently by two agents each (convergence), and the sweep also produced a substantial **confirmed-healthy** ledger — things checked expecting problems and found solid (§6).

## 1 · Executive summary

The house is structurally sound where it has been deliberately hardened — and the sweep verified that hardening firsthand rather than trusting the docs: DOOR's Gate-9 publish validators, HUB's notes-conflict save (the best-hardened write in HOUSE), HUB's date/DST projection, EXPO's atomic hub publish and its snapshot back-compatibility (validated empirically against all 44 real historical snapshots), PROOF's Tier-2 "lens never vault" invariant, and the near-perfect house-wide discipline on the D7 version contract (zero order-comparisons on version fields in three of four apps; the one exception is the already-tracked H4).

The defects cluster into five patterns, and one of them is the report's most useful structural insight:

**HOUSE has already solved almost every problem it has — once — and the solutions haven't propagated between apps.** EXPO sanitizes the shared GitHub token; DOOR and HUB read the same key raw (the exact crash EXPO fixed in v9.29 is live in two siblings). HUB cache-busts every cross-app fetch with a commented rationale; EXPO — the app with the most menu-freshness engineering — fetches DOOR and CODEX with zero cache protection. EXPO has quota-safe write machinery (`setItemSafe`); MISE, owner of one of the two largest keys on the shared origin, has none, and EXPO itself doesn't use its own helper on the anti-duplicate-publish guard's bookkeeping write. PROOF fail-louds on unrecognized routing section labels; EXPO's identical lookup silently defaults. DOOR and HUB use the noon-anchor date idiom pervasively; EXPO's Day Sheet re-derives dates from a stale anchor both repos already retired. Almost every "direction" in the findings files names an existing in-house seam — the fix is usually a port, not an invention. §7 proposes the cheap structural response.

The other four patterns: **silent failure on load-bearing writes** (a resident-registry save that includes anaphylactic room flags can fail with only a console.warn; a plating workbook silently omits days that failed to build; allergen-critical exports silently no-op offline); **enforcement blind spots** (real, substantial gates that exist on disk but never run in CI — 7 in EXPO, PROOF's entire 10-gate suite including a 1,251-line Playwright gate; plus gates that run but structurally cannot see the defect they'd need to catch — DOOR's only anaphylactic-banner test passes empty fixtures); **ceremony that isn't the boundary** (MISE's "Publish Now" is permanently disabled by one hardcoded constant buried under ~300 lines of approval checks that can never matter; a hydration "gate" that opens on a 5-second timer); and **second copies that disagree** (three site vocabularies, four version conventions, three cycle anchors of which two are stale, headcount stores with three writers and zero readers).

Nothing found rises to P0 — no live, currently-serving food-safety corruption. The two most consequential items are both *latent* food-safety integrity defects with fully traced trigger paths (§2.1, §2.2), and the single oldest one is already in DOOR's own known-vs-shown register, blocked not on engineering but on a product ruling (F2, §5).

### 2.1 · #1 — The allergen-verification gap (MERGE-3) — the sweep's most consequential finding

MISE's feed writers emit `allergens: entry.allergens || []` into **both** published feeds (`DOOR_RECIPE_DATA.json` and `recipe_production.json`), which flattens "nobody has checked" into "checked, none found." The display layer has a proper 3-state model (`contains` / `clean` / `unverified`) — but the `unverified` state triggers only on `null`, and a script census shows **all 240 seed records carry a real array, so the honest state is unreachable**; 12 of 240 production recipes have `allergens: []`, rendered as a confident "No allergens detected."

This is not hypothetical: **"Apple Crisp"** is a live, currently-published production record with zero ingredients, zero instructions, and `allergens: []` — a dish that virtually always carries gluten (and often dairy). It predates MISE's Aug-11 promotion floor (which is well-designed and explicitly self-aware of this exact failure class — but is enforced at only one UI call site, while the publish-time dry-run computes an `emptyAllergens` census and only *warns*). Downstream, the refute pass traced an even more central consumption site than the original finding: DOOR's **recipe-link restore path** (`hubAllergenToFlags`) initializes a slot's compliance flags all-false and only sets what the feed asserts — so linking such a recipe to a menu slot silently inherits "no allergens" into the exact `_flags` that drive the anaphylactic routing net. EXPO's independent conflict-scan fallback exits early on an empty allergen list, so the same stub under-flags in a second app.

**Latent today** — none of the 12 recipes is on the live menu (verified). The direction is already half-built in MISE itself: promote the existing `emptyAllergens` dry-run census from warn to block (or wire the existing `_cxPromotionFloor` ingredient-aware check into `buildPublishDryRun`), so the boundary holds at the one place that writes the shared feed. That is a ceremony→boundary move using code MISE already has.

### 2.2 · #2 — The anaphylactic banner, still wrong, and provably un-gated (D-1-3 + D-1-9)

DOOR's own `KNOWN_VS_SHOWN_FINDINGS.md` (2026-06-21) flagged C1: the red ANAPHYLACTIC ALERT banner re-scrapes raw resident tags (`r.tags.filter(t => t.startsWith('No '))`) instead of reusing the enforcer's predicate. Re-verified at HEAD across all four sinks — still open, and the refute pass sharpened it into a *deterministic* defect: `'GF'` is the only trigger in `ANAPH_TAG_TO_MEAL_FLAG` that doesn't start with `"No "`, so a gluten-anaphylactic resident's banner **structurally cannot ever name gluten** — it renders "Rooms X ()" with the lethal allergen omitted. The new contribution (D-1-9): the only door-smoke test that invokes the banner-bearing renderer passes `conflictRooms: new Set(), anaphSect: []` — the buggy branch never executes, `getAnaphAlertInfo` has zero test references, so door-smoke's 70/70 green can neither catch the defect nor confirm its eventual fix. The register names the fix precisely; what's missing is the product ruling it depends on (F2, §5) — this is the oldest open food-safety item in HOUSE and the sweep's strongest candidate for "do next."

## 3 · The five house-wide patterns

1. **Solved-once, not propagated.** Token sanitization, cache-busting, quota-safe writes, fail-loud enum guards, conflict-checked saves, noon-anchored dates, atomic multi-file publishes, owner-guarded cleanup — each exists, hardened and often gate-locked, in exactly one app, while at least one sibling has the un-hardened version of the same code. This is the highest-leverage pattern in the sweep because the fixes are ports, not designs. (§7 for the structural response.)
2. **Silent failure on load-bearing writes.** X-C-8 (registry/anaph flags), D-1-2 (plating workbook), D-1-1 (exports), M-1-2 (cost overrides vs its honest sibling), E-1-5 (the no-op-publish guard's own bookkeeping — failure silently reproduces the duplicate-publish class the guard exists to prevent), E-3-7 (settings save), X-C-9 (MISE library writes), H-1-7 (day-note add/remove without rollback). The house's own lens 5 ("degrade visibly") applied unevenly.
3. **Enforcement blind spots.** Gates absent from CI (E-3-2, P-1-10), gates that run but can't see (D-1-9, H-1-13), a prose-only flake list (E-3-3), a truncated local git history that can't distinguish "never added" from "silently dropped." MISE's glob-based runner is the pattern that cannot drift; EXPO's hand-enumerated list is the pattern that already has.
4. **Ceremony ≠ boundary.** M-2-2 (300 lines of approval guard reducible to one constant), M-2-3 (hand-frozen record-count siblings of the already-defused `CODEX_FEED_BASELINE`), D-1-4/X-B-3 (`_ghHydrated` opens on a 5s timer and duplicate fetches — "hydrated" doesn't mean hydrated), X-B-5 (`blockingEnabled: false` fossil on a gate that blocks, pinned by two tests). Each spends the credibility of the guards that matter.
5. **Second copies & vocabulary drift.** Three site vocabularies plus 7 inline HUB lists and ~11 MISE label maps (with one live landmine: MISE's cookSite dropdown can publish `'Lansdowne'`, a value EXPO's routing can never match — verified latent, zero occurrences in the live feed today); three cycle anchors (canonical Jun-7, EXPO's own Day-Sheet May-10, PROOF's May-10 ×8); four version-stamp conventions; five theme keys; `SECTION_COUNTS` with three writer pipelines and zero readers; two `renumberSteps` declarations where the later one silently wins.

## 7 · Structural recommendation (one, deliberately)

The single-file, no-build architecture is ruled and respected — so the answer to "solved once, not propagated" is not a shared library. It's the house's own knowledge pattern applied one level down: a short **"proven seams" registry** in the INSIGHTS orbit (one table: problem class → the hardened implementation → where it lives → who still lacks it), seeded from §3.1's list — `setItemSafe`, `_fetchJSON`'s bust pattern, the token sanitizer, `PublishAuth`/Test-&-Save, `pushFilesToGitHubAtomic`, the noon-anchor idiom, `escH`/`_escJsAttr`, `HUB_HOME_SITES`, PROOF's enum guard, MISE's glob test-runner. Then any session touching one of these classes in any app ports the seam instead of reinventing or omitting it, and the registry row gets checked off per app. Cheap, doc-only, and it converts this report's largest pattern into a standing workflow.
